# Currency Exchange Service

REST API для работы со справочником валют и обменными курсами. Приложение позволяет получать и добавлять валюты, просматривать и изменять обменные курсы, а также конвертировать денежные суммы между валютами.

Проект разработан в рамках изучения Java Backend и демонстрирует работу с HTTP-запросами, Servlet API, JDBC, SQL и многослойной архитектурой приложения.

## Возможности

- Получение списка валют и поиск валюты по коду.
- Добавление новых валют.
- Получение списка обменных курсов и поиск курса по валютной паре.
- Добавление и изменение обменных курсов.
- Конвертация валют по прямому, обратному и кросс-курсу через USD.
- Проверка входных данных.
- Централизованная обработка исключений.
- Формирование JSON-ответов с соответствующими HTTP-статусами.
- Хранение данных в SQLite.

## Используемые технологии

- **Java 17** — основной язык разработки.
- **Jakarta Servlet API** — обработка HTTP-запросов.
- **Apache Tomcat 10** — контейнер сервлетов.
- **SQLite** — реляционная база данных.
- **JDBC** — выполнение SQL-запросов и взаимодействие с базой данных.
- **Maven** — управление зависимостями и сборка приложения в WAR-файл.
- **Jakarta JSON Binding (JSON-B)** — преобразование Java-объектов в JSON.
- **Yasson** — реализация JSON-B.

## Архитектура

Приложение разделено на слои, каждый из которых отвечает за определённую часть работы.

```text
src/main/
├── java/
│   └── com/projectthreecurrencyexchange/
│       ├── config/       # Настройка базы данных
│       ├── dao/          # Работа с JDBC и SQL
│       ├── exception/    # Пользовательские исключения
│       ├── filter/       # Обработка исключений и HTTP-ошибок
│       ├── model/        # Модели данных и ответы API
│       ├── service/      # Бизнес-логика
│       ├── servlet/      # Обработка HTTP-запросов
│       └── util/         # Вспомогательные классы
└── resources/
    └── identifier.sqlite # Исходная база данных
```

Основной поток обработки запроса:

```text
HTTP Request
     ↓
  Servlet
     ↓
  Service
     ↓
    DAO
     ↓
   SQLite
     ↓
    DAO
     ↓
  Service
     ↓
  Servlet
     ↓
JSON Response
```

Сервлет принимает HTTP-запрос и формирует ответ. Сервис выполняет бизнес-логику, а DAO отвечает за взаимодействие с базой данных. `ExceptionHandlingFilter` перехватывает предусмотренные исключения и преобразует их в JSON-ответы с соответствующими HTTP-статусами.

## REST API

Все ответы API возвращаются в формате JSON.

### Валюты

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/currencies` | Получить список валют |
| GET | `/currency/{CODE}` | Получить валюту по коду |
| POST | `/currencies` | Добавить валюту |

Для добавления валюты данные передаются в теле запроса в формате `application/x-www-form-urlencoded`.

Поля формы:

- `name` — название валюты;
- `code` — код валюты;
- `sign` — символ валюты.

Пример запроса:

```http
POST /currencies
Content-Type: application/x-www-form-urlencoded

name=Euro&code=EUR&sign=€
```

Пример ответа:

```json
{
  "id": 2,
  "code": "EUR",
  "name": "Euro",
  "sign": "€"
}
```

### Обменные курсы

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/exchangeRates` | Получить список обменных курсов |
| GET | `/exchangeRate/{PAIR}` | Получить курс по валютной паре |
| POST | `/exchangeRates` | Добавить обменный курс |
| PATCH | `/exchangeRate/{PAIR}` | Изменить существующий курс |

В `{PAIR}` указываются два трёхбуквенных кода валют подряд. Например, `USDEUR` обозначает курс из USD в EUR.

Для добавления курса используются поля формы:

- `baseCurrencyCode` — код исходной валюты;
- `targetCurrencyCode` — код целевой валюты;
- `rate` — значение обменного курса.

Пример запроса:

```http
POST /exchangeRates
Content-Type: application/x-www-form-urlencoded

baseCurrencyCode=USD&targetCurrencyCode=EUR&rate=0.92
```

Для изменения существующего курса передаётся новое значение `rate`:

```http
PATCH /exchangeRate/USDEUR
Content-Type: application/x-www-form-urlencoded

rate=0.95
```

### Конвертация валют

| Метод | Endpoint | Описание |
|---|---|---|
| GET | `/exchange?from={CODE}&to={CODE}&amount={AMOUNT}` | Рассчитать конвертацию суммы |

Параметры запроса:

- `from` — код исходной валюты;
- `to` — код целевой валюты;
- `amount` — сумма для конвертации.

Пример запроса:

```http
GET /exchange?from=USD&to=EUR&amount=100
```

Пример ответа:

```json
{
  "baseCurrency": {
    "id": 1,
    "code": "USD",
    "name": "United States dollar",
    "sign": "$"
  },
  "targetCurrency": {
    "id": 2,
    "code": "EUR",
    "name": "Euro",
    "sign": "€"
  },
  "rate": 0.92,
  "amount": 100,
  "convertedAmount": 92.00
}
```

Примеры JSON иллюстрируют структуру ответов. Идентификаторы, курсы и результаты конвертации зависят от данных в базе.

## Расчёт обменных курсов

При конвертации приложение последовательно проверяет доступные способы расчёта:

1. **Прямой курс.** Если в базе есть курс из исходной валюты в целевую, используется он.
2. **Обратный курс.** Если прямого курса нет, проверяется курс в противоположном направлении. Для расчёта используется обратная величина курса.
3. **Кросс-курс через USD.** Если прямой и обратный курсы отсутствуют, используется отношение курсов обеих валют к доллару США.

Результат конвертации содержит исходную и целевую валюты, использованный курс, исходную сумму и рассчитанную сумму обмена. Конвертированная сумма округляется до двух знаков после запятой.

## Обработка ошибок

Для централизованной обработки исключений используется `ExceptionHandlingFilter`. Предусмотренные исключения преобразуются в JSON-ответы с соответствующими HTTP-статусами.

| HTTP-статус | Описание |
|---|---|
| `200 OK` | Запрос успешно выполнен |
| `201 Created` | Валюта или обменный курс созданы |
| `400 Bad Request` | Некорректные или отсутствующие входные данные |
| `404 Not Found` | Валюта или обменный курс не найдены |
| `409 Conflict` | Валюта или обменный курс уже существуют |
| `500 Internal Server Error` | Ошибка при обработке запроса, в том числе при работе с базой данных |

Пример ответа об ошибке:

```json
{
  "message": "Currency not found"
}
```

Текст сообщения зависит от возникшей ошибки.

## Сборка и запуск

### Требования

- JDK 17;
- Apache Maven;
- Apache Tomcat 10.

### Сборка приложения

Клонируйте репозиторий:

```bash
git clone https://github.com/KruachenkaDB/ProjectThreeCurrencyExchange.git
```

Перейдите в каталог проекта:

```bash
cd ProjectThreeCurrencyExchange
```

Соберите приложение:

```bash
mvn clean package
```

В Windows также можно использовать Maven Wrapper:

```powershell
.\mvnw.cmd clean package
```

После успешной сборки WAR-файл будет создан в каталоге `target`.

### Запуск в Apache Tomcat

1. Скопируйте WAR-файл в каталог `webapps` Apache Tomcat.
2. Запустите Tomcat.
3. Откройте приложение в браузере.

Если WAR-файл называется `ProjectThreeCurrencyExchange.war`, приложение будет доступно по адресу:

```text
http://localhost:8080/ProjectThreeCurrencyExchange/
```

Контекстный путь зависит от имени WAR-файла и настроек развёртывания.

## Настройка и хранение базы данных

В репозитории находится файл `src/main/resources/identifier.sqlite` с начальными данными о валютах. При сборке Maven этот файл включается в WAR.

При первом обращении к конфигурации базы данных приложение определяет расположение рабочей базы SQLite. Если файл по указанному пути отсутствует, приложение копирует туда исходную базу из ресурсов. Необходимый каталог создаётся автоматически.

По умолчанию рабочая база располагается в каталоге `currency-exchange` внутри домашнего каталога пользователя (`user.home`).

Например, в Windows путь может выглядеть так:

```text
C:\Users\Username\currency-exchange\identifier.sqlite
```

Приложение работает с рабочей копией базы данных. Изменения в ней не затрагивают исходный файл, включённый в WAR.

При последующих запусках, если рабочая база уже существует, повторное копирование не выполняется. Добавленные пользователем валюты и курсы сохраняются между запусками, пока рабочий файл не будет удалён или заменён.

### Настройка расположения базы данных

Расположение рабочей базы можно изменить с помощью переменных окружения:

- `DATABASE_PATH` — полный путь к файлу базы данных.
- `DATA_DIR` — каталог для хранения файла `identifier.sqlite`, если `DATABASE_PATH` не задан.

Если обе переменные не заданы, используется расположение по умолчанию.

Пример для Windows PowerShell:

```powershell
$env:DATA_DIR = "C:\data\currency-exchange"
```

Пример для Linux:

```bash
export DATA_DIR=/opt/currency-exchange/data
```

Переменные окружения необходимо задать в окружении, из которого запускается Tomcat, до старта сервера.
